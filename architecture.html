Architecture overview

Factory Inventory Management System

A two-tier demo app: a Vue 3 single-page frontend talks to a Python FastAPI backend over REST. There is no database. The backend loads JSON files into memory once at startup, then filters them per request.

Data flow: applying a filter

What happens when a user changes the Warehouse filter on the Dashboard.

  1. User picks a value in FilterBarWrites to a shared ref in useFilters.js. Because the refs are module-level, every view sees the same filter state.
  2. View reactsA watcher in the view calls getCurrentFilters(), which maps Time Period to month (e.g. 2025-03 or Q1-2025).
  3. api.js builds the requestValues equal to "all" are dropped, the rest become query params: GET /api/orders?warehouse=Tokyo&month=Q1-2025.
  4. FastAPI filters in memoryapply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() substring-matches order_date, expanding quarters via QUARTER_MAP.
  5. Pydantic validates the responseList endpoints declare response_model=List[Model]; summary, spending and report endpoints return plain dicts.
  6. Vue derives the displayRaw responses land in refs (allOrders, inventoryItems); KPIs, chart series and tables are computed properties on top.

Data model

Shared fields make filtering generic: most records carry warehouse, category and a date.

InventoryItem 32 records

sku, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location. Low stock = on hand at or below reorder point. No time dimension, so month filter does not apply.

Order 250 records

order_number, customer, items[], status, warehouse, category, order_date, expected_delivery, total_value. Drives revenue, pending counts and reports.

BacklogItem + PurchaseOrder

Backlog response is enriched at request time with has_purchase_order, joined on backlog_item_id.

DemandForecast, Spending, Transactions

Static datasets returned as-is; no server-side filtering.

Observations

Things worth knowing before changing the code.

Client calls endpoints that don't exist. App.vue calls api.getTasks() / createTask(), and api.js also defines DELETE/PATCH /api/tasks and POST /api/purchase-orders. None of these routes exist in main.py, so those calls return 404.
Inconsistent component styles. Reports.vue uses the Options API and calls axios directly with a hard-coded URL instead of going through api.js.
Unrouted view. views/Backlog.vue exists but is not registered in main.js; backlog is shown on the Dashboard instead.
Hard-coded API base URL. http://localhost:8001/api is fixed in api.js; there is no Vite proxy or env variable.
Simple to reason about. Stateless reads over in-memory lists mean every endpoint is a pure function of its query params, which keeps tests straightforward.
