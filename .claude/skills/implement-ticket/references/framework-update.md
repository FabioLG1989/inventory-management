# Framework-update prompt

Loaded by `/implement-ticket` Phase 0 only when `.framework_update.should_prompt` in `.preflight-ok` is `true` and the run is interactive. `.installed` is what this project runs, `.checkout` what the framework clone holds on disk, `.latest` what exists upstream. The opt-out is `--skip-update-check` (`QAF_SKIP_UPDATE_CHECK=1`), applied by the SKILL body before the preflight runs.

Before Phase 1, present `<installed> → <latest>`, `.action` (`sync` = resource sync; `initialize` = breaking, needs re-initialization), and `.release_notes_url` when non-null; when `.reason` is `checkout-ahead-of-install` add that the release is already in the framework checkout and only the project-side apply is missing (nothing to download); when `.migrations` is non-empty, name its entries as the migration scripts the upgrade will run for them, in the order listed — the framework runs them, the engineer does not. Ask the developer, offering "Upgrade now" and "Continue on current version"; an ask that returns no answer (no developer reachable) logs `framework update <installed> → <latest> available` and continues to Phase 1 without prompting again and without writing the decline state — this notice is informational and never STOPs the run.

- **Upgrade now** → run `bash "$WS/qubika-agentic-framework/scripts/apply-framework-update.sh" --framework-path "$WS/qubika-agentic-framework" --tag <latest> --action <action> --provider <provider>` plus one `--migration <path>` per `.migrations` entry, **in the order the array lists them** (that order is the order they must run in) (`WS` = `.workspace_root`, provider = `.provider`, both from the marker). Then **STOP regardless of its exit** and tell the engineer to re-run their original command — never continue this run on swapped-out framework files. On non-zero exit surface its stderr (e.g. it refused a dirty framework tree); when `.action` is `initialize` also tell them to run `"$WS/qubika-agentic-framework/scripts/initialize-project.sh"` first — that action is reached only when a release the upgrade crosses declares it needs a re-initialization, which supersedes every migration, so `.migrations` is empty there. On a successful sync the result's `.touched_paths` lists the project files the sync rewrote — name them and tell the engineer to commit or stash those before re-running, or Phase 0's clean-tree check will reject the re-run.
- **Continue on current version** → record the decline so this version stays quiet on later runs: `printf '{"declined_version":"%s"}\n' "<latest>" > ".claude/.framework-update-state.json"`. Then proceed to Phase 1; nothing was swapped.

When `.reason` is `check-unavailable` or `no-framework-checkout`, the SKILL body emits its one-line notice instead; this file is not read.
